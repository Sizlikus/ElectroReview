# ЭлектроКонтроль 0.4.0 — Windows-демо для схем 220–400 В

Проверки ограничены цепями переменного тока 220–400 В.
Локальная программа для сканированных PDF до 100 000 000 байт. Электротехнические
схемы, текст и пояснительные записки; строительная часть исключена. Программа не
отправляет проекты во внешние сервисы без команды пользователя. Python, Tesseract rus+eng и AES-библиотека
включены в готовую Windows-папку. Без API весь разбор и ограниченная проверка работают локально.

## Скачать и запустить

Откройте https://github.com/Sizlikus/ElectroReview/actions и успешный запуск
`Build Windows demo`. В `Artifacts` скачайте `ElectroReview-Windows-0.4.0`.
Для скачивания нужен вход в GitHub. Распакуйте весь архив в новую папку и запустите
`ElectroReview.exe`. Папки `_internal` и `ocr` должны оставаться рядом с EXE.
Администратор и установка Python не требуются. Дистрибутив не подписан сертификатом.

Проекты хранятся отдельно, в `%LOCALAPPDATA%\ElectroReview\projects`.
Версия 0.4 читает проекты версий 0.2 и 0.3. Для возврата к 0.2 сначала сделайте копию папки
проекта: старая версия не поддерживает карточки и результаты новых проверок.

## Простой рабочий цикл

1. Откройте PDF, укажите имя проверяющего и нажмите `Проверить лист`.
   OCR выполняется при необходимости в направлениях 0° / ±90°. Затем автоматически
   открывается окно проверки. Внизу показано время обработки.
2. Выберите черновик → `Сверить выбранную цепь`. Во вкладке `1. Сверить надписи`
   показаны чтения, оригинальные фрагменты с соседними линиями и редактор текста.
   Двойной щелчок включает / убирает надпись. Во вкладках параметров проверьте
   данные цепи. Неизвестное оставляйте неизвестным.
3. Сверьте текст, параметры и электрические связи с оригиналом. Поставьте галочку
   подтверждения → `Утвердить и проверить`. Выбранные чтения и карточка сохраняются
   вместе; шесть условных правил запускаются автоматически. Не нужно заранее
   утверждать все строки OCR. Невыбранные чтения остаются жёлтыми.
4. `Результаты проверки` покажут замечания и `Не проверено`. Закройте окно проверки,
   выберите замечание справа в главном окне, проверьте основание и утвердите /
   исключите его. Утверждённое замечание красное.
5. `Экспорт PDF` сохраняет схему, отметки, комментарии, подтверждённый поисковый
   слой, карточки и покрытие проверок.

Локальные черновики связывают обозначение аппарата с близкими надписями только
как предложение. Неоднозначная надпись рядом с несколькими аппаратами не включается.
Это не восстановление соединений по линиям; проверяющий устанавливает связь.
Подтверждённые источники не предлагаются повторно как новые черновики.
Не найденную цепь можно добавить кнопкой `Добавить цепь вручную`.

Старые кнопки доступны через `Расширенные инструменты`: повторное OCR, ручная
жёлтая область / замечание, разбор обозначений, карточка по выбранным строкам
и отдельный запуск правил. Повторное OCR сохраняет прежние решения.

## Необязательный ИИ-помощник

`Настроить ИИ` открывает совместимый API Chat Completions:

* **Локально — Ollama:** `http://localhost:11434/v1`. Ollama и модель устанавливаются
  отдельно; пример модели с изображениями `qwen3-vl:8b` нужно загрузить в Ollama.
  Модель не включена в архив. Доступность и скорость зависят от компьютера.
* **Облачный пример — DeepSeek:** `https://api.deepseek.com`, модель `deepseek-flash`
  (пример по документации на 10.10.2026). Пресет использует OCR-текст без изображения.
  Нужны API-ключ и квота. Регистрация в чате не заменяет API; запросы могут быть платными.
* Можно задать другой совместимый API и модель. Для передачи изображения проверьте
  поддержку vision у выбранной модели.

Настройки сохраняют только адрес, имя модели и опцию изображения. Ключ хранится
в памяти до закрытия программы, не записывается в проект, настройки или журнал.
Введите ключ в программе; не присылайте его в чат и не добавляйте в GitHub.
Запрос выполняется отдельной кнопкой `Отправить лист ИИ`. Передаются чтения только
текущего листа и при включённой опции JPEG не более 1800 × 1800 пикселей, а не весь PDF.
В окне показаны адрес назначения и модель. Облачный сервис получает эти данные
и обрабатывает их по своим условиям. HTTP допускается только для loopback-сервера;
внешние адреса требуют HTTPS. Перенаправления запросов запрещены.

ИИ возвращает черновики с источниками параметров и предупреждениями. Программа
отклоняет неверные типы/числа, отсутствующие ID надписей, параметры без источника,
дубли и незавершённые ответы. Это проверка формата и привязки, а не доказательство
правильности ответа модели. Все подсказки необходимо сверить с оригиналом.
Нормативные замечания создаёт модуль шести правил по подтверждённой карточке.
Автоматическая полная проверка нормативов через ИИ не заявляется.
При ошибке API локальный разбор доступен; запрос не повторяется автоматически.
Тайм-аут сетевой операции — 120 с; окно можно закрыть, результат не будет применён.

Документация интеграций:
https://docs.ollama.com/api/openai-compatibility
https://api-docs.deepseek.com/

## Первые шесть условных проверок

Источник: ПУЭ, изд. 7, гл. 1.7, приказ Минэнерго РФ от 08.07.2002 № 204.
Текст положений: https://legalacts.ru/doc/prikaz-minenergo-rf-ot-08072002-n-204/
Версия набора: `PUE7-1.7-subset-2026-10-10-v1`. Это ограниченный набор, а не вся
актуальная нормативная база РФ.

| Проверка | Когда выполняется |
| --- | --- |
| 1.7.126, табл. 1.7.5: PE | Подтверждены табличный метод, сечения и одинаковые материалы фазной жилы и PE. Расчётный выбор не оценивается. |
| 1.7.127: отдельный PE | Подтверждены расположение, материал, сечение и требуемые условия механической защиты. |
| 1.7.131: PEN | Подтверждена многофазная TN со стационарным кабелем, материалы и сечения фазных жил и PEN. Полный выбор PEN по 1.7.134 и гл. 2.1 не проверяется. |
| 1.7.132: однофазный PEN | Подтверждены число фаз и неприменимость исключения для ответвления от ВЛ. |
| 1.7.145: коммутация PE/PEN | Подтверждён разрыв аппаратом и отсутствие исключений. Штепсельные соединители и вводы домов от ВЛ требуют отдельной проверки. |
| 1.7.135: N и PE после разделения | Проверяющий явно установил наличие/отсутствие повторного объединения. |

Неизвестные данные блокируют соответствующий тест. «Условие выполнено» относится
к отдельному условию, а не к цепи или всему проекту. Номинал автомата и ток УЗО
распознаются справочно; их соответствие пока не проверяется. Для кабелей с разными
сечениями жил подсказка сечения не заполняется. Похожие буквы и цифры не исправляются
без проверяющего. Наличие PE не выводится из числа жил.

Критичность — предварительный экспертный индекс, не вероятность аварии:
90% для выявленного недостаточного PE, 100% для реализованных нарушений PEN,
коммутации защитного проводника и повторного объединения. Проверяющий принимает
окончательное решение; отсутствие замечаний не получает оценку «0% риска».

## Надёжность и границы

При изменении исходного чтения карточка требует повторного подтверждения, результаты
отмечаются устаревшими, связанные замечания исключаются. Их нельзя вновь утвердить
до актуализации карточки и новой проверки. Повторный запуск на тех же данных не
дублирует замечания и сохраняет решения проверяющего. Журнал фиксирует изменения.
Проверка исходного SHA-256, блокировка проекта и резервная копия JSON сохранены.
Журнал не защищён электронной подписью. Экспорт не сохраняет юридическую
действительность цифровой подписи исходника.

Автоматические графические символы, восстановление соединений по линиям/пересечениям,
детектор размытия, полная проверка ПУЭ/ГОСТ/СП, КЗ, селективность, время отключения,
токовая нагрузка кабеля, падение напряжения и проверка УЗО НЕ реализованы.
Не внесённые в карточки цепи не проверены. Геометрия схемы не является прокладкой кабеля.
Жёлтый цвет означает необходимость решения, а не установленную ошибку или размытость.
Не найденная OCR надпись может остаться без отметки. Учебная схема синтетическая.

AES-128 и AES-256 PDF с пустым пользовательским паролем поддерживаются. Для PDF,
который требует обязательный пароль, нужна доступная копия без пароля.

## Проверки

59 тестов ядра, обозначений, границ и исключений правил, устаревания результатов,
совместимости старых проектов, AES и экспорта. На учебном PDF проверена отрисовка
отметок и кириллицы. Качество на реальных проектах пока не измерено.
GitHub Windows-сборка повторяет тесты и проверяет упакованный EXE из папки с
кириллицей/пробелами без внешнего OCR в PATH: rus+eng, обе вертикальные ориентации,
AES-128/256, карточку, правило PE, PDF-результат, окна Tk, упрощённую проверку,
пакетное утверждение и локальный HTTP-запрос с синтетическими OCR + JPEG.
Живой внешний ИИ и качество его ответов на реальном проекте пока не проверены.
Архив публикуется только после успешных проверок. Фактический отчёт конкретной сборки
находится в `packaged-selftest.json`, версии зависимостей — в `python-packages.txt`
и `ocr/msys2-packages.txt`.

## Разработка

Python 3.12; `python -m pip install -r requirements.txt`, затем `python app.py`.
Тесты: `python -m unittest discover -s tests -v`.
Windows-сборка: `.github/workflows/build-windows.yml`, `scripts/build-windows.ps1`.
