# ЭлектроКонтроль 0.2.1 — локальное демо для Windows

Основной диапазон: 220/230–380/400 В. Электротехнические схемы, текст и пояснительные
записки. Строительная часть исключена. Облака и платных ИИ-API в этой версии нет.

## Получение готовой Windows-программы

Исходный ZIP НЕ является готовым EXE. EXE создаёт GitHub Actions на Windows.
Сборка содержит Python, библиотеки и бесплатный Tesseract с русским и английским языками.
Приложению после распаковки интернет не требуется.

1. Откройте https://github.com/Sizlikus/ElectroReview/actions
2. Выберите успешный запуск `Build Windows demo` для версии 0.2.1.
3. В разделе `Artifacts` скачайте `ElectroReview-Windows-0.2.1`.
4. Распакуйте весь архив в новую папку и запустите `ElectroReview.exe`.
   Папки `_internal` и `ocr` должны остаться рядом с EXE.

Программа запускается обычным пользователем. Готовая сборка не требует установки
Python, Tesseract или cryptography. Для скачивания артефакта нужен вход в GitHub.
Исходники уже находятся в репозитории; повторно загружать их не требуется.

## Исправление AES в 0.2.1

Добавлены `pypdf[crypto]` и закреплённая версия `cryptography`, включаемая в EXE.
Исправлена ошибка `cryptography>=3.1 is required for AES algorithm`.
Проверяются импорт, отображение и экспорт учебных сканов с AES-128 и AES-256,
а также корректный отказ для PDF с обязательным паролем. Ввод пароля в демо пока
не реализован: для такого файла нужна доступная копия без пароля.

## Что работает

- PDF до 100 000 000 байт, просмотр и масштабирование.
- Учебный пример, создаваемый локально по кнопке.
- Жёлтые области, увеличенный фрагмент, исправление и утверждение текста.
- Имя проверяющего, исходное чтение, время UTC и журнал решений.
- Ручные замечания с индексом критичности 1–100%; для утверждения нужно основание.
- OCR текущего листа Tesseract rus+eng. Все результаты предварительные.
- Сохранение проекта после решений; резервная копия предыдущего JSON.
- Запрет открытия одной папки проекта для редактирования в двух окнах.
- Экспорт PDF с рамками и комментариями, ведомостью и новым поисковым слоем для
  подтверждённых чтений на страницах без исходного текста.

Жёлтый цвет — необходимость подтверждения, не ошибка проектирования.
Зелёная рамка в интерфейсе — подтверждённое чтение. Красная — утверждённое замечание.
Критичность — экспертный индекс, не вероятность аварии. Непроверенное не равно 0%.

## Что исправлено по сравнению с 0.1

- Добавлена автоматическая Windows-сборка и проверки упакованного EXE.
- OCR, DLL, языки и конфигурация TSV включаются в готовую папку.
- OCR проверяется с убранным внешним PATH: не должен зависеть от установленного Tesseract.
- Готовая сборка проверяется из пути с пробелами и кириллицей.
- Проекты находятся отдельно от файлов программы, в пользовательской папке.
- Длительные загрузка, OCR и экспорт выполняются в фоне.
- Учебный проект не требует потерянного исходного PDF пользователя.
- Добавлены блокировка проекта, резервная копия, предупреждение о неутверждённом тексте.
- Ошибка пакетной проверки не открывает блокирующий диалог на сервере сборки.
- В PDF отсутствуют значки, закрывающие надписи: используются рамки с комментариями.

## Границы демо

Автоматическая нормативная проверка, распознавание электрических символов,
восстановление соединений и детектор размытия НЕ реализованы. Процент качества не заявлен.
ПУЭ и другие нормы пока не включены как верифицированная база правил.
Нельзя использовать отсутствие замечаний как заключение о соответствии нормам.

Распознавание текста не подтверждает номиналы, кабели и защиту. Поворотные, мелкие и
размытые надписи требуют ручной проверки. Для листов с исходным текстовым слоем новый
слой не добавляется; подтверждённые чтения остаются в ведомости. Исходный слой не
считается автоматически проверенным. Номера страниц PDF могут отличаться от штампов.

Прямые линии и их продолжение — полезные признаки будущего распознавателя однолинейных
схем. Пересечение без дополнительных признаков не будет автоматически считаться
соединением. Геометрия схемы не трактуется как физическая прокладка кабеля.

Журнал локальный и не защищён электронной подписью. Экспорт — производный документ,
не сохраняющий юридическую действительность цифровой подписи исходного PDF.

## Проверки и состояние сборки

В среде разработки прошли 17 тестов ядра, включая AES-128 и AES-256.
Windows-процесс сборки повторяет тесты с зависимостями из `requirements.txt`,
создаёт EXE и переносит его в папку с кириллицей и пробелами.
Пакетная проверка запускается без внешнего OCR в PATH: проверяет реальное OCR
слова «КАБЕЛЬ», импорт и экспорт AES-сканов, кириллический поисковый слой и создание
окна приложения с PDF. Архив готовой программы публикуется только после успешных
проверок. Отчёт находится в `packaged-selftest.json` готового архива.
Это проверка запуска и базовых функций, а не доказательство качества инженерной экспертизы.

## Для разработчика

Python 3.12. Зависимости закреплены в `requirements.txt`.
Локальный запуск: `python -m pip install -r requirements.txt`, затем `python app.py`.
Тесты: `python -m unittest discover -s tests -v`.
Сборка: `.github/workflows/build-windows.yml` и `scripts/build-windows.ps1`.
Версии OCR-зависимостей и контрольные суммы записываются в готовую папку.
Дистрибутив не подписан сертификатом издателя.
